Module: AI Metadata

Модуль includes/class-ai-metadata.php автозаполняет реквизиты документа по тексту первой страницы PDF. Он не подписывает файл и не меняет контрольную копию; результат используется только как подсказка для формы загрузки.

Входные данные

  • Текст первой страницы PDF, извлеченный в браузере через локальный PDF.js.
  • Имя исходного файла PDF.
  • Настройки организации из Sign_Docs_Settings.
  • Текущие термины таксономий: категории, типы документов и институции.
  • Доступный WordPress AI Client и одобренный AI connector.

Выходные данные

  • Зарегистрированная ability sign-docs/suggest-document-metadata.
  • REST endpoint POST /wp-json/sign-docs/v1/suggest-metadata.
  • Подсказки: категория, тип документа, term ID типа, институция, дата, номер, тема, краткое и полное название, confidence и warnings.

Модель

  • При настроенном OpenRouter модуль явно использует provider openrouter.
  • Единственная предпочитаемая модель: google/gemini-2.5-flash-lite.
  • Fallback-моделей нет намеренно: если ответ занимает больше нескольких секунд, администратору быстрее заполнить поля вручную.
  • Для OpenRouter передается custom option reasoning: {"exclude": true}, чтобы не возвращать reasoning-текст и не раздувать ответ.

Контракт

  • Автозаполнение включается настройкой ai_autofill_enabled; по умолчанию выключено.
  • Endpoint доступен пользователям с правом upload_files.
  • Минимальная длина текста первой страницы - 40 символов; более короткий текст считается ненадежным.
  • AI должен выбирать document_category только из slug: local-act, external-regulation, other-document.
  • document_type_term_id должен соответствовать существующему термину. Если модель ошиблась, нормализация пытается сопоставить тип по названию.
  • Дата возвращается в формате dd.mm.yyyy, номер без символа №, тема без внешних кавычек.
  • Если пользователь изменил поля после выбора файла, браузерный код не перетирает эти значения ответом AI.
  • Если AI не отвечает или возвращает ошибку, форма остается ручной и загрузка документа не блокируется.

Локальные зависимости

  • PDF.js лежит в assets/vendor/pdf.min.mjs и assets/vendor/pdf.worker.min.mjs.
  • OpenRouter provider-плагин в локальном сайте был исправлен для поддержки outputMimeType, outputSchema и формата OpenAI structured output json_schema.schema.
  • Правки provider-плагина находятся вне репозитория sign-docs и могут быть затерты обновлением плагина из WordPress.org.
