Module: Document Service

Модуль Sign_Docs_Document_Service выполняет первый вертикальный сценарий подписи PDF.

Входные данные

  • Путь к локальному PDF-файлу, доступному WordPress.
  • Краткое и полное название документа.
  • Данные подписанта: ФИО, должность, организация.
  • Исходное имя файла.

Выходные данные

  • Запись CPT sign-docs: опубликованная для завершенного документа или приватная для промежуточного состояния needs_public_copy.
  • Неизмененная контрольная копия original.pdf.
  • Публичная копия stamped.pdf появляется только после браузерного workflow prepare/complete; серверный fallback не генерирует PDF-копию.
  • Серверный SHA-256 исходной контрольной копии.
  • Meta-поля документа, включая URL проверки и данные для QR-кода.

Контракт

  • Модуль принимает только PDF с MIME application/pdf.
  • post_title хранит краткое название записи, а full_title сохраняется отдельно в meta; если полное название не передано, используется краткое.
  • Хеш считается после сохранения контрольной копии в постоянное хранилище.
  • Промежуточная запись двухфазной подписи создается приватной и публикуется только после успешного сохранения stamped.pdf.
  • При ошибке сохранения или расчета хеша запись удаляется через внутренний rollback, который не должен превращаться в пользовательское архивирование.
  • Разметка поверх страниц исходного PDF выполняется только в браузере через pdf-lib. Серверный PHP-код не должен подменять ее отдельным PDF-сертификатом.
