Module: Meta

Модуль задает контракт метаданных документа через register_post_meta().

Входные данные

  • ID записи sign-docs.
  • Скалярные значения meta: строки и целые числа.

Выходные данные

  • sha256_hash - серверный SHA-256 исходного файла.
  • original_file_path, original_file_url - контрольная копия.
  • stamped_file_path, stamped_file_url - публичная копия.
  • verification_url, qr_code_data - данные проверки и QR.
  • Данные подписанта, статус, версия, имя файла, размер и MIME-тип.
  • replaces_post_id, replaced_by_post_id, replacement_note - необязательная связь замены между самостоятельными CPT-записями.
  • prepared_at, completed_at, completed_by_user_id, completed_ip, completed_user_agent - audit-поля двухфазной подписи.
  • document_category, document_type_label, document_institution, document_date, document_number, document_subject - реквизиты для конструктора названия и классификации документа.
  • stamp_position - устаревшее поле положения основного штампа.
  • stamp_corner - выбранный угол основного штампа.
  • stamp_color - выбранный цвет штампа.
  • stamp_opacity - прозрачность рамки и текста штампа.

Контракт

  • Неизвестные meta keys не читаются helper-методами модуля.
  • Во встроенную схему WordPress REST выводятся только редакторские поля; внутренние поля original_file_path, stamped_file_path, hash исходника, QR payload, IP, user-agent и audit user IDs остаются доступны только серверному коду и кастомным endpoint-ответам.
  • REST-доступ к meta проверяется через edit_post конкретной записи, а не через общее право edit_posts.
  • Целочисленные поля проходят через absint().
  • Многострочные текстовые поля проходят через sanitize_textarea_field(), остальные строковые поля - через sanitize_text_field().
