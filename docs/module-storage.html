Module: Storage

Модуль Sign_Docs_Storage отвечает за файловое хранилище в wp-content/uploads/sign-docs и серверный SHA-256.

Структура директорий

uploads/sign-docs/
  assets/
    site-icon.png        # кэш favicon/логотипа для QR
    index.php
  YYYY/
    MM/
      {post_id}/
        original.pdf          # или {file_basename}.pdf
        stamped.pdf           # или {file_basename}-stamped.pdf
        index.php

Входные данные

  • Путь к файлу исходного PDF.
  • ID записи, timestamp и опциональный file_basename (транслитерация названия).

Выходные данные

  • Структура директорий uploads/sign-docs/YYYY/MM/{post_id}/ с index.php guard.
  • Базовые директории uploads/sign-docs/ и uploads/sign-docs/assets/ с index.php guard.
  • SHA-256 для переданного файла.

Методы

  • paths() — базовые пути: base_dir, base_url, assets_dir, assets_url.
  • ensure_directories() — создаёт базовые и assets-директории при активации плагина.
  • document_paths(post_id, timestamp, file_basename?) — пути для конкретного документа. Если file_basename задан, файлы именуются {basename}.pdf и {basename}-stamped.pdf.
  • ensure_document_directories(post_id, timestamp, file_basename?) — создаёт директорию документа и пишет index.php.
  • hash_file(path) — возвращает SHA-256 файла или пустую строку при ошибке.

Контракт

  • Исходный файл не изменяется после расчёта хеша.
  • В каждую директорию пишется index.php (silence is golden).
  • Модуль не создаёт записи WordPress и не принимает HTTP-запросы.
  • Хеш считается через hash_file('sha256').
