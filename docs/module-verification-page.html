Module: Verification Page

Модуль Sign_Docs_Verification_Page выводит публичную страницу проверки подписанного документа и регистрирует rewrite rule для коротких URL.

Методы

  • register_rewrite_rules() — добавляет правило ^signed/([0-9]+)/?$.
  • verification_permalink(permalink, post) — заменяет стандартный permalink CPT на /signed/{id}/.
  • url(post_id) — возвращает home_url('/signed/{id}/').
  • enqueue_assets() — подключает CSS и JS (public.js) на singular-странице CPT.
  • render_content(content) — фильтр the_content: выводит страницу проверки.

Содержимое страницы

  • Название документа.
  • Дата и время подписи (временная зона сайта).
  • Подписант (должность + ФИО) и организация.
  • Статус и версия документа.
  • SHA-256 исходного файла.
  • Ссылка на stamped PDF (если есть).
  • Для unsigned-документов — ссылка на исходный PDF.
  • Для active-документов ссылка на исходный PDF — только для авторизованных с edit_post.
  • Предупреждение о замене: если заменён — ссылка на новый документ; если является заменой — ссылка на предыдущий.
  • Браузерный checker: выбор локального PDF, расчёт SHA-256 через Web Crypto, сравнение с sha256_hash исходника и stamped_file_hash.

Контракт

  • Страница не должна ссылаться только на файл без отображения хеша и данных записи.
  • Выбранный пользователем файл не загружается на сервер.
  • Для статуса needs_public_copy неавторизованным пользователям возвращается 404.
  • verification_url автоматически фиксируется как короткий адрес при первом запросе.
  • Публичный контент экранируется через esc_html().
