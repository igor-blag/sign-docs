Important behavior

  • The original PDF is copied to uploads/sign-docs/YYYY/MM/{post_id}/original.pdf and remains the control copy.
  • The server calculates SHA-256 from the original PDF. This hash is the source of truth.
  • The public PDF copy is saved next to the original as uploads/sign-docs/YYYY/MM/{post_id}/stamped.pdf.
  • The QR code points to the verification page, not to a PDF file.
  • The REST flow is two-phase: prepare saves the original and creates the CPT record; browser JS stamps the PDF; complete saves the stamped PDF and marks the record active.
  • AI autofill is optional and only proposes form values. The administrator can edit all fields before saving.

Model experiments

  • google/gemini-2.5-flash-lite: working default, fastest usable option observed in the plugin flow.
  • nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free: free and multimodal, but too slow and prone to long reasoning output.
  • google/gemma-4-31b-it:free: currently rate-limited upstream.
  • deepseek/deepseek-v4-flash:free: returned upstream 402 out-of-credits.
  • openai/gpt-oss-20b:free: worked but took about 28 seconds with the full prompt and gave weaker titles.
