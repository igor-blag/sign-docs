Important behaviors

  • Original PDF → uploads/sign-docs/YYYY/MM/{post_id}/{file_basename}.pdf.
  • Server calculates SHA-256 from the original — this is the source of truth.
  • Stamped PDF → uploads/sign-docs/YYYY/MM/{post_id}/{file_basename}-stamped.pdf.
  • QR code points to /signed/{post_id}/ (verification page), never directly to a PDF.
  • REST flow is two-phase: prepare → browser stamps → complete.
  • Admin form always saves documents as unsigned via POST; the signed path must go through JS + REST.
  • AI autofill is optional and off by default.
  • Replacement workflow: new CPT links to old via replaces_post_id; on success, old gets replaced status.
  • Delete prevention: all user-facing delete/trash actions convert to archived status. Internal service rollback uses a flag to bypass this.
  • Server-side PDF generation is explicitly forbidden. Stamped PDF is never generated or substituted by PHP.

  • Admin handle_upload() fixed: both "signed" and "unsigned" buttons now always save as unsigned with defer_stamped=true. The server-side POST handler cannot generate stamped PDFs; browser JS + REST is required for signing.
  • Added includes/class-translit.php — Cyrillic-to-Latin filename transformation for filesystem-safe names.
